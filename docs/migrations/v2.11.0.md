# Upgrading to v2.11.0

The `ClaimsSign` RPC returns gRPC `INVALID_ARGUMENT` for a usage the server has no configuration for. It returned `UNAVAILABLE`, which invites a retry that can never succeed.

## Do I need to act?

**Required** if your caller checks for `UNAVAILABLE` to detect an unknown usage. A caller that signs only with configured usages, such as Authentication, sees no change.

## Handle an unknown usage as a caller error

An unknown usage fails the same way on every attempt, so the fix is a code or configuration change: send a configured usage, or register the usage on the server.

```go
// before
if status.Code(err) == codes.Unavailable {
	// unknown usage, or the service is down
}

// after
if status.Code(err) == codes.InvalidArgument {
	// unknown usage, or a payload the service rejects
}
```

`INVALID_ARGUMENT` also covers a malformed payload and a payload naming a registered claim. Do not retry any of them. `UNAVAILABLE` from `ClaimsSign` now means only that the service cannot serve the call, so a retry policy on that code stays correct.

To verify, call `ClaimsSign` with an unregistered usage and expect `INVALID_ARGUMENT` with the message `unknown usage`.

## Notes

The `core.JwkExportLocal.SearchKeys` span is renamed `core.JwkExportLocal`. Update a trace query or dashboard that filters on the old name.

No database migration or configuration change is required.
